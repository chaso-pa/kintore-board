# 1.3.0 リリース手順（オフライン対応）

PR #31。アプリ 1.3.0（iOS build 3 / Android versionCode 4）。

順番を守らないと、**旧アプリを含めて記録の保存ができなくなる**。新しいバックエンドは記録の作成・更新のたびに
`deleted_workouts` テーブルを読むので、テーブルがない状態で起動すると保存がすべて失敗する。

## 1. DB マイグレーション（PR をマージする前）

マージするとタグが付き、`backend-cd.yml` が `:latest` のイメージを push する。
本番が `:latest` を自動で取り込む構成なら、マージした時点で新しいバックエンドが動き出すので、先に適用しておく。

```bash
cd backend
DATABASE_URL=<本番の接続先> npx prisma migrate status   # 20261106060431_add_deleted_workouts が未適用であること
DATABASE_URL=<本番の接続先> npx prisma migrate deploy
```

- 中身はテーブル追加とインデックス追加だけ。旧バックエンドはこのテーブルを使わないので、先に適用しても影響はない。
- `workouts` へのインデックス追加は、行数が多いと数秒かかる。
- 開発 DB（192.168.3.100）にも同じものを適用する。

## 2. 本番の前提を確認

- [ ] サーバーのタイムゾーンが UTC（Dockerfile に `TZ` の指定はない。環境変数で上書きしていないこと）
- [ ] MySQL の分離レベルが REPEATABLE READ（`SELECT @@transaction_isolation;`）

## 3. PR をマージしてバックエンドをデプロイ

- マージコミットのメッセージに **`#minor`** を入れる（`bump-tag.yml` は既定で patch を上げる）。
- タグの push で `backend-cd.yml` がイメージを作る。デプロイ後に確認する:
  - [ ] `GET /api/v1/workouts/export` が 200 を返す（認証が必要）
  - [ ] 旧アプリ（1.2.0）で記録を保存できる

## 4. アプリのビルドと提出

ネイティブモジュール（`expo-sqlite`、`@react-native-community/netinfo`）を追加したので、ストア版のビルドが必要。

- [ ] 実機確認（`docs/offline-record-sync.md` の E2E-1〜7）を Release ビルドで行う
  - 機内モードで記録の作成・編集・削除ができる
  - 機内モードを切ると自動で同期される
  - 1.2.0 で記録したアカウントのまま 1.3.0 に上げると、過去の記録が取り込まれる
  - オフライン時に掲示板・ジム・マシンの書き込みボタンが押せず、閲覧はできる
- [ ] iOS: Archive → App Store Connect に提出
- [ ] Android: AAB を作って Play Console に提出（`docs/google-play-submission.md` §3）

App プライバシー / データセーフティの申告は変更不要。トレーニング記録は以前から「フィットネス」として申告済みで、
端末内に保存する場所が増えただけで、外部に送るデータは変わっていない。

### What's New（App Store / Google Play 共通）

```
・電波がない場所でもトレーニング記録をつけられるようになりました。記録は端末に保存され、オンラインに戻ると自動で同期されます。
・記録の詳細画面から記録を削除できるようになりました。
・オフライン中は画面上部にお知らせを表示し、掲示板・ジム・マシンは閲覧のみになります。
・アップデート後の初回起動時に、これまでの記録を端末に取り込みます。
```

## 5. 問題が起きたとき

- **バックエンドだけ戻す場合:** 前のタグのイメージに戻せばよい。`deleted_workouts` テーブルは残っていても旧バックエンドに影響しない。
  ただし新アプリの削除は、旧バックエンドでは「削除済み」が記録されないため、別の経路で同じ ID が再送されると復活しうる。
- **アプリ:** OTA（expo-updates）は入れていないので、修正はストア版の再提出になる。
