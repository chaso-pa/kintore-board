## このアプリについて

筋トレ向けの匿名掲示板 + ユーザー投稿型のジム/マシンDB + トレーニング記録アプリです。
iOS / Android（Expo / React Native）。バックエンドは自前サーバー（Go）と自前ホストの
オブジェクトストレージ（MinIO）。

以下は実装を確認して裏を取った事実です。**ここに書いていないことは書かないでください。**
実態と食い違うポリシーは、ストア審査でも実害でも問題になります。

### アカウントとログイン

- **ログイン機能はありません。** 初回起動時に端末で生成した UUID をサーバーへ送り、
  匿名アカウントが自動作成されます。
- **Google / Apple などの外部認証プロバイダは使っていません。**
- **氏名・メールアドレス・電話番号・生年月日は一切取得しません。** サーバーの users
  テーブルにもそれらのカラムはありません（保持するのは UUID・状態・権限・作成日時のみ）。
- 認証トークンと利用者IDは端末の Keychain / Keystore（expo-secure-store）に保存します。

### サーバーへ送信・保存されるもの

| 種別 | 内容 |
| --- | --- |
| 識別子 | 端末で生成した UUID（匿名アカウントの識別） |
| 投稿 | スレッドのタイトル・本文、レス本文。**表示は匿名**だが内部的にアカウントに紐づく |
| ジム情報 | 名称、住所、緯度経度、ビジター料金、月額料金、説明文 |
| マシン情報 | 名称、メーカー、対象部位、備考 |
| 写真 | ジム・マシンの写真（利用者がアップロードしたもの） |
| トレーニング記録 | 日付、メモ、種目名、重量、回数、セット数、セットごとのメモ、補助の有無、部位 |
| 通報 | 通報対象の種別とID、理由コード、任意の説明文、通報したアカウントのID、日時 |
| 操作 | 保存したジム、保存したスレッド、「役に立った」投票 |

### 通報とモデレーション

投稿・スレッド・ジム情報・マシン情報を通報できます。ポリシーには次の点を書いてください。

- 通報時に保存されるのは、**対象・理由・任意で入力した説明文・通報したアカウントのID・日時**です
- 通報内容は**運営（管理者権限を持つアカウント）が確認します**。確認のため、運営は通報された
  投稿やジム情報の内容を閲覧します
- **通報したことは相手に通知されません**
- 通報の対応結果を通報者へ個別に通知する仕組みはありません
- 同じ対象への重複通報は1件として扱われます

また、ジム・マシン・写真の新規登録は**公開前に運営の承認を経ます**（登録者本人には承認前も
表示されます）。この審査のために運営が内容を閲覧することも書いてください。

### 位置情報

- 「近くのジムを探す」機能でのみ使用します（利用中のみ / When In Use）。
- 緯度経度は**検索クエリとして送信されますが、サーバーには保存していません。**
- ただしストアのデータ収集申告上は「収集」に該当する扱いです。

### アクセスログ（※先に私に確認してください）

**この項目は、私に確認するまで書かないでください。** 断定できる材料が揃っていません。

コードから確実に言えるのはここまでです。

- サーバーのプロセスは、リクエストごとのログ行を**標準出力に出力**します。この行には
  接続元IPアドレス、日時、アクセス先パス、HTTPステータスが含まれます
- 運営がモデレーションの判断（承認・却下・削除）を行うと、実行した管理者アカウントのIDと
  対象が同じく標準出力に出ます
- **アプリはIPアドレスをデータベースに保存していません。** IP用のカラムは存在せず、
  コード内でIPを読み書きしている箇所もありません。ログファイルへの書き出し設定もありません

つまり「標準出力に出る」ところまでが事実で、**それが保存されるかどうかは、コンテナをどう
実行しているか次第**です。その設定はアプリのリポジトリに含まれていないため、こちらでは
判断できません。

`docker run` のログドライバ（既定の json-file ならホスト上のファイルに蓄積されます）、
ログ収集基盤の有無、ローテーション設定 — このいずれかを私に聞いてから、

- 保存しているなら: 取得項目と目的、保持期間を書く
- 保存していないなら: 「アクセスログを保存していない」と書く、または項目自体を置かない

のどちらかにしてください。**「IPアドレスを保存しています」と決め打ちで書かないでください。**
実態と違う可能性があります。

### 端末内にのみ保存されるもの

- 利用者が作成したカスタム種目の一覧、カスタム部位の一覧、非表示にしたプリセットの一覧
  （アプリ内のファイル。アプリを削除すると消えます）

**注意**: これらの「一覧」は端末内だけですが、**その種目名・部位名を実際に記録に使うと、
記録の一部としてサーバーに送信されます。** 「カスタム種目・部位は一切外部送信されない」
とは書かないでください。

### 第三者サービス

- **地図表示**: react-native-maps を使用。iOS では Apple マップ、Android では Google マップ
  が地図データを提供します。地図の表示にあたり、位置情報が各社に送信され得ます。
  それぞれのプライバシーポリシーへのリンクを記載してください。
- 写真は**自前ホストのオブジェクトストレージ**に保存します（外部のクラウドストレージ
  事業者は経由しません）。

### 使っていないもの（これらは「利用していない」と明記して構いません）

- **広告 SDK は一切ありません**（AdMob 等）。パーソナライズ広告もありません。
- **解析 SDK はありません**（Firebase Analytics / Amplitude / Mixpanel など）。
- **クラッシュレポート SDK もありません**（Sentry / Crashlytics など）。
- **広告識別子（IDFA / AAID）は取得しません。**
- 購入履歴・連絡先・検索履歴の収集はありません。

### 権限

| 権限 | 用途 |
| --- | --- |
| 写真ライブラリ | ジム・マシンの写真を追加するため |
| 位置情報（利用中のみ） | 近くのジムを表示するため |

### データの削除

アプリ内で削除できるもの:

- **自分が投稿したスレッド・レス**（本人のみ。運営も削除できます）
- トレーニング記録（1件ずつ削除可）
- 保存したジム、保存したスレッド、マシンとジムの紐付け

**ここが重要です。投稿の削除は論理削除です。** 削除すると他の利用者からは見えなくなりますが、
**サーバー上のデータは即座には消去されません。** 通報への対応記録として、運営が「何が削除
されたか」を確認できる状態で保持します。ポリシーには、

- 削除すると他の利用者からは閲覧できなくなること
- 運営側の記録としては保持されること
- 完全な消去を希望する場合は問い合わせ先へ連絡すること

を書いてください。**「削除すると完全に消えます」と書かないでください。事実と違います。**

削除**できない**もの（実装がありません）:

- **アカウント自体の削除（退会）**
- 登録したジム・マシン・写真

これらの削除を希望する場合は問い合わせ先に連絡する旨を書いてください。
**アプリ内に退会機能があるかのような書き方はしないでください。**

### 保存期間

現時点で自動削除の仕組みはありません。断定しにくいので、「利用目的の達成に必要な期間
保持し、削除の申し出があった場合は対応する」といった書き方にしてください。

### 対象年齢

**子ども向けアプリではありません。** 匿名の投稿機能があります。年齢確認や年齢制限の
実装は現時点でありません。

### データの国外移転

サーバーは運営者が管理するもので、大手クラウドの海外リージョンは使用していません。
地図表示に関して Apple / Google へデータが渡り得る点は該当します。

## 書いてはいけないこと

実装が無いので、次を書くと嘘になります。

1. **利用者をブロック・ミュートできる**（未実装。通報はできますが、特定の相手を非表示に
   する機能はありません）
2. **アプリ内で退会・アカウント削除ができる**（未実装）
3. **投稿を削除すると完全に消去される**（論理削除です）
4. **カスタム種目・カスタム部位は外部送信されない**（記録に使えば送信されます）
5. **NGワードフィルタや自動検知がある**（未実装。掲示板の投稿は事前審査なしで公開されます）
